# 02｜回归测试与验收流程

## 测试目标
Skill 每次修改后，重新运行12个案例，确认没有出现以下退化：
- 文字变短了，但具体含义丢失；
- 术语数量减少了，但正文仍难懂；
- 案例变多了，却没有事实依据或没有标注为假设；
- 为追求通俗，删除专业条件；
- 所有内容被改成同一种模板；
- 已经清楚的文字被过度改写。

## 测试步骤
1. 将案例中的“原始表达”作为输入。
2. 使用 Skill 生成优化版。
3. 对照案例参考答案，比较核心意思是否一致。
4. 使用100分评分表打分。
5. 记录本轮新增问题。
6. 修改 Skill 后重新运行受影响的案例和完整回归集。

## 必须做的反向测试
除了测试难懂内容，还要输入一段本来就清楚、准确、结构合理的文字。

合格的 Skill 应判断“无需大改”，只修正真正有问题的部分。不能为了显示自己有用而强行重写。
