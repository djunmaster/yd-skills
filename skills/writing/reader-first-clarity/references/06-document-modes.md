# 06｜不同文档类型的表达模式

## 1. 概念解释
顺序：一句话定义 → 为什么需要 → 怎么运作 → 具体例子 → 术语说明。

## 2. 业务分析
顺序：业务目标 → 参与者 → 业务动作 → 解决的问题 → 结果和风险 → 岗位职责。

## 3. 技术文档
每项功能尽量明确：
- 触发条件；
- 输入信息；
- 系统处理；
- 输出结果；
- 失败或异常情况；
- 权限和限制；
- 验收方法。

## 4. 产品需求/招标要求
不要只写“系统应支持某功能”。应尽量写成可验证要求：
- 在什么条件下；
- 哪类用户或系统发起；
- 系统要执行什么动作；
- 应返回或保存什么结果；
- 异常时如何提示或处理；
- 如何测试通过。

## 5. 比较分析
先明确比较对象和维度，再说明：
- 相同点；
- 差异点；
- 差异对用户工作的影响；
- 适用条件；
- 尚未确认的内容。

## 6. 操作指南
采用编号步骤。每一步写清动作、判断条件和完成标志。重要风险放在相关步骤附近。

## 7. 管理汇报
先给结论，再给关键数据和依据，随后说明影响、风险、建议和待决策事项。避免空泛的战略语言。

## 8. 学习材料
从基础概念开始，按难度递进；每个关键概念配一个例子；必要时加入“请用自己的话复述”的检查题。
