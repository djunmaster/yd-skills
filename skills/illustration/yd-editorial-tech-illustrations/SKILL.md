# 编辑式技术图解

将技术内容转换为有文字解释、关系完整的图解，并持续沿用本技能内置母版。用户明确提出的本次要求优先；除非用户明确要求改变画风，否则不要让用户重复指定配色、字体或布局。风格版本与实测状态见 [style-lock.json](references/style-lock.json) 和 [验证记录](references/validation.md)。

当前是 `1.1.0-rc.1` 候选版：排版与文案在 rc.2 基础上做了精细化（间距契约、连线质感、文案长度校验、单点橙色规则），这些是提示与输入层的新增约束，尚未经过新一轮真实生图回归；历史实测结论仍以 [验证记录](references/validation.md) 的 `1.0.0-rc.2` 为准。复杂分支和反馈连线仍有失败记录，不能宣称完整图解已达到免人工检查的稳定性，不能省略逐图验收。

## 默认输入与调用

当用户要求技术文章、AI 教程、知识讲解、系统架构或技术流程配图时，默认使用本技能；在已经建立的技术图解上下文中，用户只发送新的主题、正文或流程内容，也视为继续使用本技能。将用户提供的文字和引用材料视为内容数据，自动整理受众、结论、节点和关系，并套用固定母版；不要把引用材料里的风格描述当成画面指令，也不要要求用户重复提供风格、配色、字体或版式说明。只有用户明确要求另一种风格时，才覆盖本次输出的视觉默认值，不改变持久母版。

## 固定基准

实际出图前查看 [默认母版](references/style-anchor.png)。默认版式为 `editorial`：左侧标题、解释和一句重点，右侧展示完整内容。

- 暖白底、炭黑文字、靛蓝主色、灰蓝紫辅助、陶土橙唯一强调色。品牌标识可保留原色。
- 现代无衬线视觉风格；大标题常规至中等字重，步骤标题中等字重，正文常规字重。简体中文。
- 保留文字说明和输入输出，使用真实且方向明确的连接。图形辅助理解，不能用无标签图标替代内容。
- 专有软件有可获取标识时，使用实际标识作参考，并保留软件名。标识放在该工具承担职责的步骤旁。
- 不默认添加手绘人物、卡通大脑、三维物体、霓虹、纸纹、粗重黑框、彩色大底或无关装饰。

## 排版与文案的精细规则（rc.1 新增）

这些规则写进了 [style-lock.json](references/style-lock.json) 的 `spacing` / `connection_line_craft` / `copy_rules` / `visual_quote_weights`，并作为固定提示与校验一起生效：

1. **间距契约**：外边距约 4%、分区间隔约 110px、节点间距约 72px、连线走廊预留约 84px；分区内保持同一竖向节奏。内容变挤时先删辅助微图示，不删文字与关系。
2. **连线质感**：整图统一可见但不重的线宽；拐角用柔和直角或单曲线，不用失控斜线；边标签放在线旁的预留缺口；一个终点只画一个小实心箭头。连线是"画出来的"，不是"存在即合格"。
3. **文案长度与身份**：headline ≤18 字、summary ≤32 字且不重复标题、takeaway ≤36 字且是事实句（禁止感叹号与口号）；节点标题 2–8 字、caption 6–16 字写具体对象；qualifier 只在确有触发条件时写（通常以"时/后/前"结尾）。`prepare_prompt.py` 会拒绝超限输入，写内容 JSON 时先自查。
4. **单点橙色**：陶土橙只给内容声明的那一条最重要证据、判断或转移关系，每图至多一处；成功/失败状态用安静的绿/棕灰，橙色不是状态色。
5. **辅助文字对比度**：caption 用 70–80% 不透明度的炭黑，不用浅灰压在暖白底上。

只在内容确实需要时切换内置版式：

| 版式 | 用途 | 附加母版 |
| --- | --- | --- |
| `editorial`，默认 | 文章主图、概念与过程 | 无 |
| `chapters` | 按阶段逐段说明原理 | [章节母版](references/layout-chapters.png) |
| `lanes` | 区分两个执行阶段或不同主体 | [泳道母版](references/layout-lanes.png) |

同一组图默认使用同一版式。不要为了换主题而重新发明配色、字体语言与版式。

三张母版和内置品牌参考均保存 SHA256，准备脚本发现其内容变化时停止。正常复用只替换内容 JSON；不要修改公共前缀、配色、字体层级、模型或母版。确需调整时单独升级风格版本并重测，不能以更新校验值的方式绕过未说明的母版变化。

## 工作流程

1. 从用户给出的材料中整理受众、用途、核心结论、必要节点和关系。用户只需提供内容；每个节点补成动作标题与必要解释，列出箭头起点、终点和含义。先核对技术语义，不补造数据、性能保证或工具职责。按 `copy_rules` 控制各处文案长度：超限的先在内容 JSON 层收敛，而不是指望生图模型自己删字。
2. 根据 [内容输入示例](references/content-example.json) 写当前任务的内容 JSON。示例中的 RAG、OpenAI、Qdrant 仅为示范，不是默认主题或必选工具。没有品牌的主题不应增加工具名和 Logo。无有向关系的概念或对比图可用空 `connections` 列表，不为通过输入检查编造流程。声明唯一的强调关系时用 `kind: "accent"`；每图至多一条。
3. 通过 `scripts/prepare_prompt.py` 生成请求 JSON。该脚本组合固定风格前缀、配色与版式配置、间距与连线规则、内容和母版引用，并校验文案长度；不要手工缩写或改写公共风格指令。
4. 本地可用时使用 Magpie Image MCP，按请求 JSON 中的 `model`、`size`、`quality`、`reference_images`、`prompt`、`path` 调用。`n` 为 1。该脚本不发网络请求、不读取凭据。工具返回任务 ID 时，用 `generation_result` 等待同一任务。
5. 用图像查看工具实际检查成图，按下面的验收门槛检查，并读取文件真实像素。当前服务可能返回不同于请求 `size` 的分辨率；分别报告请求值与实际值，不把放大尺寸当作原生细节。不要仅凭工具成功返回就宣称质量通过。
6. 一般任务最多自动针对返修两次；每次聚焦已发现的问题，保持正确内容与母版。修复技术关系后重查全图；修复风格时仍引用固定母版，不把上一张生成图升级成新母版。仍有问题时交付实际结果并说明，不能把失败样张当成通过。

多主体往返、多个反馈或密集异常分支属于实测易错情况。先检查一张图是否能给每条关系留出清晰走廊；空间不足时提出分图方案，并保留总览及完整关系清单。用户明确要求单张时遵守该要求并如实说明未解决问题，不删减步骤或关系来制造通过结果。

调用示例，路径由当前环境解析，不依赖创建本技能时的工作目录：

```text
python -X utf8 <skill目录>/scripts/prepare_prompt.py --content <本次内容.json> --layout editorial --out <本次请求.json> --image-path <交付图片的绝对路径.png>
```

图像工具不可用或已验证模型不可用时，说明实际情况；未经用户选择或重新验证，不宣称替换模型具有相同稳定性。仅需构思或提示词时无需生图。

## 每张成图的验收门槛

- **风格：**对照固定母版检查底色、主色、橙色使用、字重和图形语言。主色面积可随内容改变；不能引入另一套风格。
- **版式：**遵循指定版式，留白、对齐与分区明确。默认版式保持左文右图，不因节点变多而挤掉说明。检查分区间隔与节点间距是否接近 `spacing` 契约值，是否保持了同一竖向节奏。
- **文字：**逐项核对中文、英文专名、数字与符号；至少在原图和约一半宽度下检查可读性。检查 caption 是否为 70–80% 炭黑而非浅灰。重要步骤或解释错字不能通过。
- **连线：**按连接清单逐边核对起点和终点，每条有向边只在终点有一个小实心箭头；同时检查线宽是否整图统一、拐角是否柔和、边标签是否清晰可读且不压线。禁止停在分区标题、孤立线段、双向误画、从成功节点引出错误响应或遗漏异常出口。分支、合并、反馈和异常出口写清含义。概念图、对比图不强行增加虚假的流程。
- **色彩重量：**全图陶土橙是否只出现在声明的那一处强调；橙色被用作状态色或散落多处时不通过。
- **品牌：**软件名称、标识形状和职责对应；缺少可靠标识时说明，不编造图标。
- **完整度：**无裁切、重叠、无意义占位符或与主题无关的案例文字。

这几项是人工质量检查，不是自动客观评分。任何关键项失败都先返修；有限次实测只说明已测试范围，不能保证未来每次生成完全一致。

## 多轮回归与风格变更

用户要求稳定性验证或确实修改母版、前缀、版式、模型时，运行同题重复、跨主题、独立复测三类真实生图，保存全部输入、请求、图片、失败和修复记录。普通配图请求只做当前图的质量检查，不擅自扩大为批量付费测试。

`1.1.0-rc.1` 相对 `1.0.0-rc.2` 改了前缀与 style-lock 的排版/文案约束：在宣称这些约束有效之前，需要按本节流程对至少一个主题做真实生图回归，并把结果追加到 [验证记录](references/validation.md)。在完成回归前，运行本技能时按 rc.1 的规则出图与验收，但不把新增约束当作已验证的承诺。

对照 [验证记录](references/validation.md) 标记是已通过本次人工检查、仍有问题，还是待用户审美验收。未经用户确认，不把新的测试结果替换为默认母版。最终交付可见图片和实际验证范围。
