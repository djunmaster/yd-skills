# 可复用方法论参考

## 来源提炼

可参考的图文分享页把长文拆成大量 `data-visual-*` 视觉卡片。卡片标题涵盖时间线、结构图、对比图、流程图、闭环、架构分层、清单、案例卡组、交互演示、指标图和条形图。共同表达模式是：

- 先从口语或长文中提炼一个关系句。
- 让图形承载关系、顺序、层级、比较或约束。
- 用文字补充来源、判断、边界和行动建议。
- 一个卡片只表达一个核心关系；多个卡片覆盖整段内容。
- 案例通常按“问题→简化/改造→数据动作→验证”展开。

长文与口述材料的整理经验进一步说明：高质量图解不是给文字加装饰，而是把原文中的对象、空间、阈值、分布、角色和版本关系直接画出来。参考图的共同语法是深色底、少色线稿、目标框、虚线、局部高亮与一段明确的图注结论。

## 数据建设主线

可复用闭环：

`定场景 → 明确输入输出 → 合规采集 → 清洗与标准化 → 标注 → 质量评估 → 训练/使用 → 失败样本回流 → 版本记录`

质量检查至少覆盖：重复、缺失、异常、逻辑约束、单位、命名、编码、元数据、来源权限、隐私、长尾、同源增强、训练测试泄漏和图像/视频对齐。

五类问题的默认数据动作：

| 问题 | 首选动作 | 关键边界 |
|---|---|---|
| 真实样本少、敏感数据采不到 | 真实业务样本 + 有约束的合成补位 | 合成数据不得替代真实评估集 |
| 数据规模大但分散 | 采集→清洗→加工→标注流水线 + 量化指标 | 指标要绑定版本与计算口径 |
| 标注成本高、专家分歧大 | AI 预标注 + 专家复核 + 双盲校正 + 第三方仲裁 | AI 不独立决定最终标签 |
| 隐私重、不能直接开放 | 脱敏、标准标注、指令样本、资产登记与授权 | 合规文件包必须随数据交付 |
| 知识频繁变化、需要引用 | 知识库/RAG + 定期增量刷新 | 不把实时知识问题硬塞给微调 |

## SVG-first 视觉语法

长文改写时，先把每个有独立含义的段落映射成一种视觉关系。优先选择下面这些“可观察关系”，而不是默认套流程图：

| 原文关系 | 应该画什么 | 不要怎么画 |
|---|---|---|
| 对象与输入输出 | 带类型的文件、设备、文本、图像、字段与映射箭头 | 只写“输入/输出”两个空框 |
| 阈值、等级、越界 | 有规则时画对应区间与映射；缺规则时分别画位置事实、待补判据和可能输出 | 自造阈值，或给未分类曲线强配三色等级 |
| 空间连接、包含、相交 | 目标框、连接线、重叠区域、判定箭头 | 只画一条流程箭头 |
| 长尾与分布 | 真实柱状图；无实测值时画相对示意并标明 | 用精确数字或看似实测的柱高 |
| 角色协作与复核 | 角色卡、谁产出什么、双盲隔离、分歧仲裁 | 把“AI 预标”和“专家复核”塞进同一条直线 |
| 版本与迭代 | 数据版本、模型版本、指标与失败样本的对应轨迹 | 只列“V1/V2/V3”三个词 |
| 流水线与运营 | 传送带/数据产线、阶段节点、质量门槛、反馈回路 | 用通用方框箭头代替业务对象 |
| 判断表与方法选择 | 每项画具体缺口与所选动作，例如覆盖空位、专家答案分歧、文档版本替换 | 六条文字卡配一张总图，或只给图标 |
| 执行清单与操作建议 | 每步画示例输入、实际字段变化、隔离关系或交付产物 | 只列编号和动词，没有具体示例 |

每张图必须回答一个关系问题，并同时具备：标题、关系句、关键标注、图注结论。若原文没有数值，使用关系、结构或明确标示的教学示例。案例、判断表与执行清单都逐项核对解释覆盖，图数由内容决定。字段对照必须能看出实际变化，不能只有抽象名词方框。

## 常见缺口与对应做法

以下是可复用的判断套路，与具体行业无关；真实项目须按自己的材料核对，不能直接照搬结论。

1. 真实样本稀缺或敏感：用真实业务记录保证任务真实性，合成样本只补已确认的稀缺与边界缺口，并标明哪些是合成的。
2. 数据要规模化：不能只做一次性采集，需要固定流水线、量化质量指标和长期运营责任，才可能沉淀成可复用规范。
3. 人工标注成本高、专家分歧大：机器预标注产出候选，多人独立复核，分歧再交仲裁；把分歧结论回流成下一轮标注规范。
4. 数据要对外流通或复用：先汇聚、脱敏和标准标注，再按来源授权与用途范围准备登记和审查材料；脱敏或登记本身不等于已获准流通。
5. 知识频繁变化：不必先做微调，可先把聊天记录与文档过滤、切分、组装成可检索知识库，并随文件变化定期刷新。

## 微调决策

- 先建立 eval 基线，再比较提示词、检索、工具和微调。
- SFT：稳定任务映射、格式、分类、抽取、领域表达。
- DPO/偏好优化：风格、取舍、排序、摘要偏好。
- RAG：知识经常变化、需要外部事实与引用。
- 视觉/多模态微调：图像输入理解的系统性错误。
- 业务规则、权限和实时数据必须由系统控制，不能寄希望于模型参数记忆。

## 外部资料

- OpenAI Model optimization: https://platform.openai.com/docs/guides/fine-tuning
  - 先做 eval，建立真实输入基线，再进行提示词和微调迭代。
  - 微调可用于稳定格式、任务行为和特定领域输入输出；方法应按任务目标选择。
- Hugging Face Datasets features: https://huggingface.co/docs/datasets/main/en/about_dataset_features
  - 数据集 schema 应明确列名、类型、标签和嵌套结构；多模态字段保留可追溯的路径、字节和采样信息。
- DVC Versioning Data and Models: https://dvc.org/doc/use-cases/versioning-data-and-models
  - 用版本控制把数据、代码、模型、指标和处理过程连成可回溯历史，支持复现、审计和协作。
