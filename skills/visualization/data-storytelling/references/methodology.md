# 可复用方法论参考

## 来源提炼

用户提供的 7 个腾讯 AI 录音笔分享页内部包含 99 个 `data-visual-*` 视觉卡片元数据。卡片标题涵盖时间线、结构图、对比图、流程图、闭环、架构分层、清单、案例卡组、交互演示、指标图和条形图。共同表达模式是：

- 先从口语或长文中提炼一个关系句。
- 让图形承载关系、顺序、层级、比较或约束。
- 用文字补充来源、判断、边界和行动建议。
- 一个卡片只表达一个核心关系；多个卡片覆盖整段内容。
- 案例通常按“问题→简化/改造→数据动作→验证”展开。

后续补充的课程转写进一步说明：高质量图解不是给文字加装饰，而是把原文中的对象、空间、阈值、分布、角色和版本关系直接画出来。参考图的共同语法是深色底、少色线稿、目标框、虚线、局部高亮与一段明确的图注结论。

## 数据建设主线

可复用闭环：

`定场景 → 明确输入输出 → 合规采集 → 清洗与标准化 → 标注 → 质量评估 → 训练/使用 → 失败样本回流 → 版本记录`

质量检查至少覆盖：重复、缺失、异常、逻辑约束、单位、命名、编码、元数据、来源权限、隐私、长尾、同源增强、训练测试泄漏和图像/视频对齐。

五类问题的默认数据动作：

| 问题 | 首选动作 | 关键边界 |
|---|---|---|
| 真实样本少、敏感数据采不到 | 真实业务样本 + 有约束的合成补位 | 合成数据不得替代真实评估集 |
| 数据规模大但分散 | 采集→清洗→加工→标注流水线 + 量化指标 | 指标要绑定版本与计算口径 |
| 标注成本高、专家分歧大 | AI 预标注 + 专家复核 + 双盲校正 + 第三方仲裁 | AI 不独立决定最终标签 |
| 隐私重、不能直接开放 | 脱敏、标准标注、指令样本、资产登记与授权 | 合规文件包必须随数据交付 |
| 知识频繁变化、需要引用 | 知识库/RAG + 定期增量刷新 | 不把实时知识问题硬塞给微调 |

## 可视化 SVG 叙事语法（反框线图）

整理任何复杂材料时，**先立整页逻辑主线，再把每个核心章节的机制、界面或对比画成具象的 SVG 视觉画面**，而不是把每句话硬塞进“几个矩形框 + 箭头”：

| 原文逻辑/关系 | 应该画成什么 SVG 视觉画面（通过去字可辨检验） | 不要怎么画（框线图反模式） |
|---|---|---|
| 软件/对话/代码/日志/文档交互 | **可视化界面工作台**：深色窗口标题栏、代码行号与红绿 diff 条、带头像的消息气泡流与高亮选区括号、抽离出的带引用标签卡片 | 只画“输入/输出”两个文字方框加一根箭头 |
| 阈值、等级、曲线越界 | **示波/监测仪表视窗**：低对比网格底、半透明关注区间带、高对比曲线、交点锚点圆点；缺规则时仍拆开事实与待补规则 | 空白底画一根孤立曲线，或自造三色波形阈值 |
| 空间连接、包含、相交、现实设备 | **现实场景 + 局部放大镜**：一致朝向的物体轮廓、地面参考线、高亮活动部件、虚线定位框与圆形放大镜特写 | 写着“设备”“现场”的空方框和流程箭头 |
| 长尾与分布、样本缺口 | **覆盖托盘 / 密度视图**：实心样本块构成高频区，稀缺位留出橙色虚线空槽，斜纹合成补片精准对准空槽；无实测值标明示意 | 用精确数字或看似实测的柱高，或纯文字框 |
| 角色协作与双盲复核 | **双盲隔断工作台**：顶部样本分送左右工位，中间立起斜纹隔断墙，左右不同颜色判定印章触发橙色冲突灯，导向仲裁规范台 | 把“AI 预标”“专家 A/B”排成四个普通方框 |
| 隐私脱敏、合规与防泄漏 | **前后分屏文档 + 物理遮蔽/隔离墙**：左卡高亮暴露敏感字段，过光学滤镜后右卡盖上斜纹遮蔽条；固定考卷加挂锁与红色斜纹防火墙 | 并排两张纯文字表格框 |
| 版本与热更新 | **活页版本架 / 前后景深切换**：旧版变暗退回归档槽，新版高亮推到激活槽并发出绿色引用射线指向回答出处 | 只列“V1/V2/V3”三个矩形框 |
| 质量门与流水线分拣 | **扫描分拣闸**：带字段格的样本卡过扫描光束，四格齐绿灯通过，带虚线空槽的卡被挡板分流滑入退回槽 | 把“采集/清洗/加工/标注”装进四个同款方框 |
| 整页总览与多章节逻辑 | **带 `1–6` 编号路标的视觉全景地图** + 图外 `.story-roadmap` 因果主线 | 一张堆满 10 个词的复杂总流程图 |

具体画法、四层视觉质感与 `<defs>` 素材模板见 `references/visual-svg-cookbook.md`。

## HTML 页面整体逻辑与 1、2、3、4、5、6 分点叙事法

不要把长页面做成“每个独立关系画一张 480px 小框图 + 几句零散文字块堆叠”。整页必须有清晰的**三层逻辑骨架**：

1. **整页因果主线（Hero + `.story-roadmap`）**：
   - 开篇用一句主判断点题，紧接着给出 `1 → 2 → 3 → 4 → 5 → 6`（按材料实际章节数，一般 4–6 章）可点击逻辑路标。
   - 每个路标不是孤立名词，而是一句推进问题，例如：`1. 痛点根因 → 2. 拆解机制 → 3. 质控防线 → 4. 合规与防泄漏 → 5. 选型判断 → 6. 落地执行`。
2. **章与章之间承上启下（`.section-bridge` + `.next-bridge`）**：
   - 每章开头用 `.section-bridge` 一句话交代“上一章解决了什么 / 留下了什么新问题，因此本章要看什么”。
   - 每章结尾用 `.takeaway` 收束判断，再用 `.next-bridge` 自然引向下一章。
3. **章内「可视化 SVG 主图 + 1、2、3、4、5、6 分点联动拆解」（`.logic-points`）**：
   - 每章优先用 **1 张宽幅可视化 SVG 画面（`viewBox` 约 `920×420`）**，在画面关键部位放置圆形编号锚点 **`1`、`2`、`3`、`4`、`5`、`6`**。
   - 图下紧接 `<ol class="logic-points" data-for-visual="...">`，按 **`1、2、3、4、5、6`** 逐点展开逻辑：每点包含**序号徽章 + 加粗核心判断 + 逻辑角色标签（如现状痛点/核心机制/关键动作/风险边界/结果输出）+ 1–3 句因果说明**。
   - 如果某一个分点（例如第 4 点）包含独立的空间反例、局部机关或精细对比，在该分点内部嵌入一张 `.point-visual` 局部特写 SVG，保持在逻辑流之内，不脱离正文散落成卡片墙。

## 五个案例的方法映射

1. 信创固件：真实业务代码、修复记录和跨端开发能力提供真实性；合成样本补稀缺与敏感缺口；最终形成覆盖补位、定位、缺陷迁移的指令集。
2. 信息通信运维：日志与工单不能直接训练，需要“单到单”流水线、量化质量指标和长期运营机制，才可能沉淀行业标准。
3. 接入网标注：人工成本高、专家分歧大、长尾样本少；用 AI 预标注、专家双盲复核和第三方仲裁提升效率，同时把分歧回流成下一轮规范。
4. 缺陷数据资产：先汇聚、透明化和标准标注，再把复现条件与处置方案组织成指令样本，按来源授权、用途范围与实际要求准备登记和流通审查；脱敏或登记本身不等于已获准流通。
5. 非结构化知识：不需要微调也能先把聊天记录和文档过滤、切分、组装成可检索知识库，并随文件变化定期刷新；这适合知识频繁变化的场景。

## 微调决策

- 先建立 eval 基线，再比较提示词、检索、工具和微调。
- SFT：稳定任务映射、格式、分类、抽取、领域表达。
- DPO/偏好优化：风格、取舍、排序、摘要偏好。
- RAG：知识经常变化、需要外部事实与引用。
- 视觉/多模态微调：图像输入理解的系统性错误。
- 业务规则、权限和实时数据必须由系统控制，不能寄希望于模型参数记忆。
