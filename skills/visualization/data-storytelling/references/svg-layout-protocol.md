# SVG Layout Protocol v1

## 核心原则

语义结论由可追溯的证据和适用规则支持，坐标由数值决定，几何由浏览器验证。几何 `PASS` 不代表可读性或语义正确性通过；生成模型也不能依靠“看起来差不多”来判断间距或连线。

## 语义与证据门槛

- 每张图只表达一个关系，分别核对原文陈述、可观察信息、业务启发规则和输出结论。来源未提供的判别条件标为“待定义/待补”，示意内容明确标为示意。
- 目标检测框只定位候选对象；框相交是图像平面上的框关系，不证明真实接触。即使外观可见接触，也不能据此证明电气接通或合规接地。课程中的简化判别保留为有来源的业务规则，不升级为已证实物理事实。
- 现实对象的前后朝向、外形、铰链位置、开合方向和连接点应相互一致，并能追溯原文图像、现场照片或可靠结构参考；缺少参考时标“结构示意，细节待核实”，不将绘图当作现场证据。对象、场景、规则和结果有独立关系时拆成多张 SVG。
- 曲线图明确轴的变量、方向、单位和范围；来源未给出的含义标为待补，抽象坐标标为示意，不默认把横轴解释为时间。并列比较统一尺度；若单位或量纲不同，说明归一化依据或分开呈现。
- 若图声称某类别对应某曲线或区域，类别标签应就近标注或用引线直接绑定该可见对象，图例只作辅助。不能用一条未分类曲线旁的多个孤立色块替代映射；类别只是规则的可能输出时，标输出含义即可，不强配多色波形。
- 等级阈值、边界条件和持续时长须有来源。教学自选值只能在明确标为“示意，非判别标准”的独立示例中使用；原文规则缺失时保留“读曲线事实 → 独立专家规则（待补）→ 等级输出”，不对示意曲线直接判级。

## 必填契约

声明 `data-layout-contract="v1"` 的 `figure.viz` 进入完整契约审计；未声明契约的旧图进入文字/路径基础扫描，不再静默跳过。新生成的复杂 SVG 图解默认全部使用该契约。

**可视化画面优先声明 `data-visual-mode`**：新图应在 `figure.viz` 上声明视觉模式，优先选择 `interface`（可视化界面/工作台）、`scene`（现实/空间场景）、`metaphor`（视觉隐喻）、`mechanism`（可视化机关/原理）、`before-after`（视觉前后分屏）、`cutaway`（立体分层/剖面）或 `chart`（仪表/曲线观测屏）；只有纯拓扑流程才是 `diagram`。完整画面构建技法见 `references/visual-svg-cookbook.md`。

完整图文页的案例分组、判断表和执行清单可声明 `data-required-visuals="id-a id-b"`。每个 id 必须在该分组内唯一对应含 SVG 的 `figure.viz`。审计器返回逐组覆盖结果；缺图、重复图或只有文字卡时失败。结构覆盖不证明图有解释作用，仍应对照原文检查具体对象、前后变化、条件和操作产物。

当可视化 SVG 内含编号锚点（`1`、`2`、`3`、`4`、`5`、`6`）并配图外分点逻辑说明时，在 `<ol class="logic-points" data-for-visual="<visual-id>">` 中用 `data-point="1"` … `data-point="6"` 对齐，审计器会自动核对图文编号同步。

## 可视化图画与界面 SVG 扩展规则

为了支持真正的“视觉画面 / 可视化界面”，同时不放松几何安全底线，协议明确区分**节点关系连线**与**画面内部视觉标注**：

1. **画布宽度分层**：
   - 章节主视觉界面/机制画面：推荐 `viewBox="0 0 920 420"` ～ `960×460`，占满卡片宽度；不要把复杂界面硬塞进 `480×300`。
   - 局部特写/分点嵌入式小图：推荐 `viewBox="0 0 560 300"` ～ `680×340`，只放大单一零件、反例或对比细节。
2. **背景舞台层（`data-backdrop="true"`）**：
   - 舞台网格、坐标底纹、背景分区线可放入 `<g data-backdrop="true">`；仅当有效描边透明度 `<= 0.28`（或使用 `<defs><pattern>` / `stroke="none"`）时，审计器不将其视为前景碰撞障碍。严禁把真实关系线放进 `data-backdrop`。
3. **编号锚点（`data-callout-badge="1"`…`"6"`）**：
   - 锚点圆/胶囊图形加 `data-badge-shape="true"`（建议半径 `r >= 14`），数字使用 `14px`、字重 `800`。审计器自动检查数字完全落在锚点图形内（防 `BADGE_TEXT_OVERFLOW`）、各锚点互不重叠（防 `CALLOUT_BADGE_OVERLAP`）且不超出 `viewBox`。
4. **特征引线（`data-callout-leader="1"`）**：
   - 用于从编号锚点或图外短标签精准指向界面/物体内部的某个具体细节（如某一行代码、某条消息气泡、某个铰链或空槽），末端配 `r="3.5"` 圆点落在该特征上。
   - 特征引线允许使用简洁折线或克制的曲线，**不加 `data-link`**（避免与节点边界连接规则冲突），但仍接受全图描边穿字审计，绝不能压过任何文字。
5. **去框线图审计（`VISUAL_TOO_SCHEMATIC`）**：
   - 当图声明 `data-visual-mode` 为 `interface`、`scene`、`metaphor`、`mechanism`、`before-after` 或 `cutaway` 时，审计器会统计除普通节点外框和连线外的具象视觉原语数量；若几乎只有空方框与连线，会报 `VISUAL_TOO_SCHEMATIC` 警告。

## 坐标与间距

| 对象 | 最小规则 | 推荐值 |
|---|---:|---:|
| viewBox 安全边距 | 24 | 32 |
| 节点水平/垂直间距 | 16 | 24–40 |
| 节点文字内边距 | 8 | 10–14 |
| 连线与节点净距 | 6 | 12 |
| 连线与文字净距 | 4 | 8 |
| 平行连线间距 | 8 | 12–16 |
| 箭头端点误差 | 18 | 0–2 |

坐标优先使用 4 的倍数；长文本拆成两行或移到图注，不要把节点撑到相邻区域。

整图缩放同样会破坏这些数值。窄屏下把 SVG 缩到 viewBox 以下时，字号、线宽和净距会按同一比例缩水：标称 14px 的标签在 0.98 倍下只有 13.7px，审计会报 `FIGURE_SHRUNK`。因此每张图都要按自己的 viewBox 宽度声明下限：

```html
<figure class="viz" style="--viz-min-w: 980px" data-visual-id="…" data-layout-contract="v1">
```

`scripts/build_recap.js` 与 `scripts/assemble_story.js` 会按每张图的 viewBox 宽度自动写入这个变量；手写页面时补上同名声明。窄屏靠横向滚动而不是缩小整图，并且必须给出可见的滑动提示，否则报 `SWIPE_HINT_MISSING`。

## 视觉权重

几何不碰撞不等于读者能看懂。每张图必须有一个视觉焦点，并用线宽、字号、字重和对比度建立主次：

| 层级 | 用途 | 推荐值 |
|---|---|---:|
| 主对象框/关键路径 | 读者首先要识别的对象或关系 | 2–3px |
| 普通容器/次要路径 | 结构分组和辅助连接 | 1.8–2.2px |
| 辅助线/内部细节 | 只补充形状或背景信息 | 1.5–2px |
| 关键标签/结论 | 对象名称、步骤、判断、指标 | 14–18px，700–800 |
| 解释文字 | 字段、来源、边界 | 12–14px，常规字重 |

不要通过让整张图都变粗来提高可读性。先加粗主对象、主路径和结论，再降低背景线条的视觉权重。颜色只做辅助，标签必须能够独立说明含义。

当原文同时包含场景、规则、步骤和结果时，使用多个 `figure.viz`，并在图外用编号或 `.logic-strip` 连接阅读顺序。不要把注意事项、证据边界和完整解释塞进 SVG 角落；这些内容放进 `.takeaway`、`.caution`、`.evidence` 或 `figcaption`。

## 版面分区

1. 标题带：`y=0–64`，只放分区标题，不放连接线。
2. 主内容区：节点、对象和连线；左右各留 24px 安全边距。
3. 标注带：连线文字单独占用 16–24px 高的空带。
4. 回流/底线：放在内容区下方至少 16px，避免穿过主节点。

每张图最多承载一个关系。节点超过 7 个、连线超过 8 条或需要三次以上拐弯时，优先拆成两张图。

## 节点规则

- 流程与抽象关系图的独立节点使用 `<g data-node="唯一-id">`，不能只给裸 `<rect>` 加属性，也不能把多个独立节点合成一个节点规避扫描。
- 现实物体的零件需要接触或固定时，用一个 `data-node` 表示该局部装配，并用 `<g data-object="零件-id">` 分别标识零件，外部标签不并入装配。装配内的物理接触不适用流程节点的 16px 间距；全部描边仍必须接受文字碰撞扫描。
- 目标框用 `data-target-for="对象的-id"` 绑定带 `id` 的对象组，自动核对是否完整覆盖该对象。几何覆盖只能检查框的位置，标签与对象的语义仍需人工复核。
- 零件或特征标注的引线末端落在实际所指特征上；标记铰接点时应指向铰接圆点，不能停在邻近盖板内部。引线与完整对象的近似邻接不能替代特征对应。
- 节点文字必须在组内，并保留 `data-text-padding`。
- 容器和子节点允许嵌套；被包含的子节点必须有自己的 `data-node`。
- 不能用负 margin、transform 或视觉覆盖来“挤出”空间。
- 同层节点至少 16px 间距；优先按列对齐，而不是逐块手工微调。

## 连线规则

- 连线必须是 `<path data-link="唯一-id" data-from="..." data-to="...">`。
- 默认使用水平/垂直线段和 90° 拐弯，不使用斜线表达结构关系。
- 端点必须落在源/目标节点边界；不要悬空、穿过节点或深入节点。
- 每条关系线的 `data-from/data-to` 必须非空并对应本图的真实节点，箭头尖端与路径终点绑定。优先用 `marker-end`，将 marker 的 `refX` 对齐箭头尖端；不要另画一个游离三角形来补箭头。关系端点以 0–2px 误差为目标，不能扩大容差来容纳悬空。
- 读者必须能说出“谁把什么送到哪里”。反馈箭头明确业务使用/评估的来源、待处理内容和下一轮的具体动作；需要复核的候选不能直接画成真值。解释这些环节会挤占主线时，拆成独立反馈图。
- 修改旧图的关系箭头时，将整张关系图升级为 `v1` 并标记各独立节点。基础描边扫描的 `PASS` 只证明已检查的碰撞项目，不能作为端点已验证的证据。
- 同一源节点的多条线可以共享主干，并用 `data-lane-group="bus-a"` 声明共享通道。
- 平行线不得贴在一起；不同来源的分支必须分配独立通道。
- 默认零交叉。只有语义上确实需要“汇合/总线”时才允许交叉，并加 `data-allow-crossing="true"`，同时在图注解释原因。

## 标签规则

- 连线标签使用 `data-link-label` 和 `data-for` 绑定连线。
- 标签放在独立标注带，距连线至少 8px，距节点至少 6px。
- 标签不压在路径上，不用节点内部文字代替路径说明。
- 标签过长时缩短到 2–6 个汉字，完整解释放到图注。

## 绘制顺序

1. 先定节点网格和空白通道，再写任何箭头。
2. 先接端点，再写拐弯；每条线只经过预留通道。
3. 最后放标签，确保标签不占用节点和路径的空间。
4. 运行几何审计，并按语义与证据门槛独立复核；针对失败原因修正，规则或证据错误不能只靠移动坐标处理。
5. 连续两轮仍失败时，拆图或减少节点，不继续堆坐标。

## 自动审计

```powershell
python scripts/audit_svg_layout.py output.html --channel msedge --strict `
  --json layout-report.json --screenshot layout-check.png
```

审计会检查：

- 节点重叠与最小间距
- 节点文字内边距与文字重叠
- 连线穿节点、穿文字、端点悬空
- 连线交叉与平行线过近
- 标签压线、贴节点
 - 元素超出 viewBox 或安全边距
 - 整图渲染宽度小于 viewBox（`FIGURE_SHRUNK`）
 - 需要横向滚动的图缺少可见滑动提示（`SWIPE_HINT_MISSING`）
- 浏览器控制台和页面脚本错误

`--strict` 必须通过，且语义和可读性审核通过后才可交付。旧图的基础扫描也必须通过；若只有 `SKIP` 没有有效扫描结果，视为未完成，不得声称布局已验证。明确披露的规则待补可以保留，但不能声称已完成该规则验证或据此作出实际判级。

所有图先执行描边基础扫描，再对契约图追加节点和连线检查。基础扫描用 `getBBox()` 获取文字边界、`getScreenCTM()` 统一坐标、`getTotalLength()` 与 `getPointAtLength()` 采样路径，报告 `TEXT_PATH_OVERLAP`、`TEXT_LINE_OVERLAP` 和 `TEXT_LABEL_TOUCHES_STROKE`；不得因声明 `v1` 或合并装配而跳过普通描边。带 `data-target-for` 的框同时检查对象引用和几何覆盖，报告 `TARGET_OBJECT_MISSING` 或 `TARGET_BOX_MISS`。

## 常见修复

| 错误码 | 首选修复 |
|---|---|
| `NODE_OVERLAP` | 删除低价值节点，或增加一列/一行，不缩字号 |
| `NODE_GAP_TOO_SMALL` | 扩大列/行间距 |
| `TEXT_PADDING_TOO_SMALL` | 扩节点、缩短文案或移到图注 |
| `TEXT_OVERLAP` | 把标签移到独立标注带 |
| `LINK_CROSSING` | 调整节点顺序，或拆分总线 |
| `LINK_THROUGH_NODE` | 从节点外侧通道绕行 |
| `LINK_THROUGH_TEXT` | 文字移出通道或换线位 |
| `LINK_ATTACHMENT_MISS` | 端点对齐节点边界 |
| `LINK_ENDPOINT_MISSING` | 为关系线绑定非空且存在的源、目标节点 |
| `LINK_FROM_UNKNOWN` / `LINK_TO_UNKNOWN` | 修正节点引用，不用空白位置或说明文字代替目标 |
| `LINK_LABEL_TOO_CLOSE` | 标签上/下移 8–12px |
| `VIEWBOX_OVERFLOW` | 扩展 viewBox 或收回安全区 |
| `FIGURE_SHRUNK` | 给该图声明 `--viz-min-w: <viewBox 宽度>px`，不要靠缩小整图适配窄屏 |
| `SWIPE_HINT_MISSING` | 在 `.viz-scroll` 或外层 `.viz-card` 上补可见滑动提示 |
| `TEXT_PATH_OVERLAP` | 把文字移出路径通道，或改道路径 |
