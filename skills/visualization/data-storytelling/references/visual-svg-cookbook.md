# Visual SVG Cookbook：从“框线图”升级为“可视化 SVG 画面”

本手册用于解决一个高频退化问题：当材料讲的是逻辑、机制、规则、软件流程或业务方法时，模型很容易偷懒画成“几个圆角矩形 + 文字 + 直线箭头”的**框线图**。

框线图只能当大纲，不能真正帮助读者“一眼看懂”。本 skill 的默认视觉产出是**可视化 SVG 图画 / 界面场景图**：把抽象逻辑画成读者一眼能认出来的**界面、物件、空间、机关或状态变化**，再用编号锚点（`1`、`2`、`3`、`4`、`5`、`6`）与图外的分点逻辑说明一一联动。

---

## 一、核心硬判据：去字可辨检验（Text-Removal Test）

画完或设计任何一张非纯流程图的 SVG 前，先做一次**去字可辨检验**：

> **假设把图中所有中文文字全部打码抹掉，只留图形轮廓、色块、符号和排版——读者还能看出这张图在讲什么界面、什么物体、什么机制或什么对比吗？**

- **不合格（退化为框线图）**：抹掉字后，画面只剩下几个大小相近的圆角矩形和几条直角箭头。读者完全看不出“这是聊天窗口”“这是代码修复”“这是双盲隔断”还是“这是脱敏滤镜”。
- **合格（可视化 SVG 画面）**：抹掉字后，读者依然能一眼看出画面形态——比如左侧是带头像和气泡的聊天窗口、右侧抽出了一张带引用标签的知识卡；或者中间有一道隔离墙把两张工作台分开；或者左侧文档上盖上了斜纹遮蔽条。

### 图文面积预算

- **60%–75% 给视觉画面本身**：窗口框架、界面控件、物体轮廓、空间分区、物理屏障、局部放大镜、状态指示器、高亮对比区。
- **25%–40% 给精准标签与编号锚点**：短标题、关键特征标注、圆形编号锚点（`1`、`2`、`3`、`4`、`5`、`6`）和引线。
- **长解释一律移出 SVG**：完整因果分析、条件边界、为什么这么做，放进图下的 **`1、2、3、4、5、6` 编号分点说明（`.logic-points`）**，不要往 SVG 的方框里塞四五排小字。

### 画布尺寸分级（不要再用 480×300 硬塞画面）

窄小的 `480×300` 在保证 14px 最小字号和 24px 安全边距后，几乎画不下任何真实视觉画面，是导致“退化为两三个方框”的直接诱因。按视觉角色选画布：

| 视觉角色 | 推荐 `viewBox` | 适用场景 | 页面放法 |
|---|---:|---|---|
| **章节主视觉画面**（默认首选） | `0 0 920 420` ～ `0 0 960 460` | 完整可视化界面、机制场景、双盲工作台、前后分屏、带 `1–6` 编号锚点的主图 | 占满 `.viz-card` 全宽，图下紧接对应 `1–6` 分点逻辑说明 |
| **中等对比 / 双态画面** | `0 0 760 360` ～ `0 0 840 400` | 左右状态对比、局部机制切换、带放大镜的场景 | 占满全宽或嵌入 `.point-visual` |
| **分点局部特写图** | `0 0 560 300` ～ `0 0 640 340` | 嵌在某一个编号分点（如第 4 点）下，专门放大一个细节或反例 | 嵌在 `.point-visual` 中，不脱离正文单独堆砌 |

## 二、七类可视化 SVG 图画原型（替代默认框线图）

遇到不同逻辑内容时，按“**要让读者看见什么**”选择画面原型，而不是一律套流程图：

| 逻辑内容 | 优先选用的视觉原型 | `data-visual-mode` | 画面该怎么画（具象视觉元素） | 禁止怎么画 |
|---|---|---|---|---|
| 软件/AI/产品交互、日志、对话、代码、知识库检索 | **1. 可视化界面场景**（`interface-scene`） | `interface` | 带顶部三点控制栏的深色窗口、代码行号与红绿 diff 条、终端报错提示条、聊天头像与消息气泡、搜索框与高亮引用片、状态胶囊 | 两个空矩形写“输入/输出”加一根箭头 |
| 设备、车辆、现场、工位、空间位置、检测框 | **2. 现实场景与局部放大镜**（`physical-scene`） | `scene` | 一致朝向的物体轮廓、地平线/支撑面、高对比活动部件、`data-target-for` 虚线定位框、圆形放大镜视窗（`.s-loupe`）加切线引出微观细节 | 写着“设备”“车辆”的文字方框 |
| 过滤、质检、双盲复核、版本切换、权限隔离、飞轮 | **3. 视觉机制与物理隐喻**（`metaphor-mechanism`） | `metaphor` | 见下方“高频抽象逻辑的视觉隐喻词典”：分拣扫描闸、双盲磨砂隔断墙、锁封档案箱与斜纹防火墙、空位插槽与斜纹补片、前后抽拉版本架 | 把“采集/清洗/标注”或“专家 A/B”装进四个同款方框 |
| 治理前后、脱敏前后、重构前后、错误 vs 正解 | **4. 视觉前后分屏**（`before-after-stage`） | `before-after` | 左侧杂乱/暴露/异常界面，中间一道**视觉转换滤镜 / 光学扫描带 / 分屏滑杆**，右侧整齐/斜纹遮蔽/验证通过界面 | 上下两个纯文字表格框 |
| 曲线、阈值、信号越界、性能区间、监控指标 | **5. 仪表视窗与信号示波屏**（`instrument-chart`） | `chart` | 仪器外框、低透明度网格 `<pattern>`、半透明关注区间带、高对比曲线、越界交点圆点与垂直参考线、状态指示灯（缺规则时仍只标观察事实） | 空白底上画一根孤立波浪线 |
| 系统架构、权限层级、数据底座、多端分层 | **6. 分层立体面板 / 剖面**（`cutaway`） | `cutaway` | 错位叠放的半透明深色层板（带透视倾斜或阶梯错位）、垂直光束/通道穿过各层、每层内部画出代表性微型元素（文件/齿轮/锁/界面） | 三条水平扁矩形堆成汉堡包 |
| 全文总览、多阶段演进、案例地图 | **7. 视觉叙事全景地图**（`story-map`） | `scene` | 串联全页核心章节的具象缩略场景站点，带清晰的 `1 → 2 → 3 → 4 → 5 → 6` 路标锚点，与整页 `.story-roadmap` 编号一致 | 堆满 10 个词的复杂总流程图 |

## 三、高频抽象逻辑的视觉隐喻词典

很多时候原文没有汽车、设备这类现实物体，而是纯业务或技术逻辑。此时不要退回框线图，直接选用以下**视觉化机关 / 界面隐喻**：

1. **信息降噪 / 对话切分 / 检索抽取** → **消息流窗口 + 选区高亮括号 + 抽离出的索引卡片**
   - 视觉特征：左侧窗口有顶部栏和 3 个窗口点；每条消息有圆形头像和气泡；相关消息带蓝边与高亮选区括号；无关噪声（如闲聊）低对比变暗并加删除线；右侧呈现抽出组装好的带 `[引用ID]` 与版本胶囊的知识卡。
2. **代码修复 / 规则变更 / 字段映射** → **分屏代码编辑器 / 结构化 diff 视窗**
   - 视觉特征：左侧代码面板带行号、红色 `-` 删除行与波浪报错下划线、底部红色报错条；右侧带绿色 `+` 补丁行与绿色校验通过徽章。
3. **双盲复核 / 多角色协作 / 分歧仲裁** → **物理隔断双工位 + 印章冲突警报 + 仲裁规则台**
   - 视觉特征：顶部一张待审样本卡分送左右两侧；中间立起一道**斜纹半透明隔断墙（不可互见）**；左右两侧工位各画人物剪影与不同颜色的判定印章；当印章不一致时，下方亮起橙色冲突指示器，导向摊开的规范书/仲裁台。
4. **隐私脱敏 / 合规审查 / 权限边界** → **实体档案卡 + 斜纹遮蔽条 + 光学滤镜 + 锁封授权章**
   - 视觉特征：左侧表单暴露橙色高亮敏感字段；穿过中间的光学滤镜/遮罩条后，右侧同一位置的敏感信息覆盖为**斜纹遮蔽条（`.s-censor`）**，而业务故障字段以蓝色高亮完整保留；旁边另配带挂锁图标的授权清单。
5. **质量门槛 / 拦截退回 / 异常处理** → **扫描分拣闸 + 缺口插槽 + 退回滑道**
   - 视觉特征：样本卡带 4 个字段格（已填为实心小格，缺失为橙色虚线空槽）；经过竖直扫描光束闸门时，四格齐全的卡绿灯直行，带虚线空槽的卡被挡板分流向下滑入退回补录槽。
6. **长尾缺口 / 合成数据补位** → **任务覆盖托盘 + 发光虚线空槽 + 斜纹合成补片**
   - 视觉特征：多行整齐的实心蓝色样本块代表高频真实数据，稀缺位置留出一个明显的**橙色虚线空槽（`.s-socket`）**，一块带斜纹图案（区分真实与合成）的补片正对准槽位插入并挂“待复核”标牌。
7. **固定测试集 / 防泄漏评估** → **加锁密封考卷盒 + 红色斜纹隔离墙 + 双模型仪表对比台**
   - 视觉特征：顶部为带挂锁图标的冻结考卷盒（`T1`），向右/下分别连到两台模型评测仪表盘（`M1`、`M2`）；考卷盒与训练池之间画一道清晰的**红色斜纹隔离墙**与禁止回流标记。
8. **知识库热更新 / 版本切换** → **活页版本槽 + 前后景深切换**
   - 视觉特征：旧版 `v1` 卡片变暗退居后层归档槽，新版 `v2` 卡片高亮推到前层当前激活槽，发出一束绿色引用射线指向右侧问答窗口的 `[出处: v2]` 徽章。

## 四、四层 SVG 视觉质感规范（严格遵循深色技术色板）

严禁使用刺眼霓虹、彩虹渐变或玻璃拟态。高级感来自**层次景深、克制的表面对比、语义斜纹与精准标注**：

### Layer 0：画布舞台层（`data-backdrop="true"`）
- 用深色凹陷舞台底 `#131822`（`.s-stage`）承托视觉画面，与卡片 `#1d2432` 拉开第一层景深。
- 可在 `<defs>` 中定义低对比点阵或蓝图网格 `<pattern>`，铺满舞台底（`stroke="none"` 或 `opacity="0.18"`），让画面像精密工程视窗而非黑漆漆一片。

### Layer 1：主视觉对象 / 界面层（`data-node` 或 `data-scene`）
- **窗口感**：用顶部 `28–32px` 标题栏（`.s-chrome`）+ 3 个 `r="4"` 小圆点 + 简洁窗口名，瞬间建立“软件界面”视觉锚点。
- **纸张 / 文档感**：右上角切出 `14–16px` 折角（dog-ear）+ 几条圆角短横线作为视觉内容骨架（skeleton lines），比光秃秃矩形更具象。
- **景深层次**：背景/归档元素用 `#181e2b` 低对比描边；主体表面用 `#21293c` 或克制的深蓝灰纵向线性渐变（`#263047 → #1c2333`）；焦点面板加 `2.5px` 语义边框与极浅同色底（`rgba(125,151,245,0.10)`）。

### Layer 2：语义信号与质感纹理层（`<defs>` 复用原语）
- **斜纹填充（`<pattern>`）**：专门区分“非普通实心元素”——
  - 橙色斜纹 `hatchOrange`：脱敏遮蔽区、合成补片、双盲隔断墙、待复核区。
  - 红色斜纹 `hatchRed`：隔离防火墙、禁止回流区、拦截报错区。
  - 蓝色斜纹 `hatchBlue`：关注区间、选中高亮带。
- **视觉符号原语（小而准，不堆砌）**：挂锁（冻结/合规）、放大镜圆环（局部细节）、对勾/叉号徽章（通过/拦截）、印章外框（专家判定）、波浪/脉冲线（信号）、气泡尖角（对话）、插槽虚线框（缺口）。

### Layer 3：编号锚点与精准引线层（与 HTML `1、2、3、4、5、6` 联动）
这是连接“可视化 SVG 图画”与“逻辑分点说明”的桥梁：

```xml
<!-- 示例：编号锚点 1（置于画面清晰空位，不遮挡核心元素） -->
<g data-callout-badge="1">
  <circle data-badge-shape="true" cx="62" cy="76" r="14" fill="#7d97f5" stroke="#0f1218" stroke-width="2"/>
  <text x="62" y="81" text-anchor="middle" fill="#0f1218" font-size="14" font-weight="800">1</text>
</g>
<!-- 精准引线 + 目标小圆点（需要指向内部某个视觉特征时使用） -->
<path data-callout-leader="1" d="M76 76 H112" fill="none" stroke="#a3b5f8" stroke-width="1.8"/>
<circle cx="112" cy="76" r="3.5" fill="#a3b5f8"/>
```

规则：
1. 锚点圆形半径 `r="14"`～`16`，字号 `14px`、字重 `800`，并加 `data-badge-shape="true"` 以便审计器校验数字完全落在圆内。
2. 锚点颜色与语义一致：默认主线 `#7d97f5`（蓝），验证/通过 `#51cf66`（绿），风险/转换/待补 `#f0955c`（橙），隔离/报错 `#f28b82`（红）。
3. 锚点顺序按阅读视线自然推进（通常左→右、上→下），依次为 **`1`、`2`、`3`、`4`、`5`、`6`**。
4. 引线用 `data-callout-leader="<n>"`（不加 `data-link`，这样允许末端圆点精准落入界面或物体的具体特征部位），但仍须严格避开所有 `<text>`，严禁压字。
5. 图外紧邻的 `<ol class="logic-points" data-for-visual="<visual-id>">` 中，每一条 `<li class="logic-point" data-point="1">` … `data-point="6"` 与图内编号**一一对应**，审计器会自动检查编号是否同步。

## 五、可复用 `<defs>` 视觉素材模板

在复杂可视化 SVG 的 `<defs>` 中按需引入（注意每张 SVG 使用带 `visual-id` 前缀的唯一 id，防止同页冲突）：

```xml
<defs>
  <!-- 1. 低对比点阵舞台背景 -->
  <pattern id="demo-dots" width="20" height="20" patternUnits="userSpaceOnUse">
    <circle cx="2" cy="2" r="1.1" fill="#384367" opacity="0.45"/>
  </pattern>

  <!-- 2. 橙色语义斜纹（遮蔽 / 合成 / 隔断 / 关注区） -->
  <pattern id="demo-hatch-orange" width="10" height="10" patternUnits="userSpaceOnUse" patternTransform="rotate(45)">
    <line x1="0" y1="0" x2="0" y2="10" stroke="#f0955c" stroke-width="2" stroke-opacity="0.35"/>
  </pattern>

  <!-- 3. 红色语义斜纹（隔离墙 / 禁区 / 阻断） -->
  <pattern id="demo-hatch-red" width="10" height="10" patternUnits="userSpaceOnUse" patternTransform="rotate(45)">
    <line x1="0" y1="0" x2="0" y2="10" stroke="#f28b82" stroke-width="2" stroke-opacity="0.38"/>
  </pattern>

  <!-- 4. 克制的深色表面微渐变 -->
  <linearGradient id="demo-surface" x1="0" y1="0" x2="0" y2="1">
    <stop offset="0%" stop-color="#263047"/>
    <stop offset="100%" stop-color="#1c2333"/>
  </linearGradient>

  <!-- 5. 箭头（精确对齐 refX=10） -->
  <marker id="demo-arrow-blue" viewBox="0 0 10 10" refX="10" refY="5" markerWidth="9" markerHeight="9" markerUnits="userSpaceOnUse" orient="auto">
    <path d="M0,1 L10,5 L0,9 z" fill="#7d97f5"/>
  </marker>
</defs>
```

## 六、交付前可视化自检清单

1. **去字可辨**：抹掉文字后，画面是否仍能看出具体界面、场景、机制或对比？（绝非均匀方框 + 箭头）
2. **主次分明**：全图只有一个视觉重心，背景舞台低对比，主体清晰，焦点高亮。
3. **编号同步**：图内 `1`、`2`、`3`、`4`、`5`、`6` 锚点是否按自然阅读顺序排列，并与下方 `.logic-points` 的 `1、2、3、4、5、6` 分点完全对应？
4. **字号与留白**：核心文字 `>= 14px`，说明文字 `>= 12px`，文字与所有实线、边框、图形零碰撞。
5. **证据诚实**：画面中的界面文案、数据示例、结构细节是否如实标明“教学示意 / 来源 / 待核实”，绝不因追求好看而伪造真实数值或未经核实的结论？
