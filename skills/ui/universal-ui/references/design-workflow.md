# Universal UI 设计工作流

这个流程用于新页面、新工具、整页原型或跨项目复用。局部替换一个小组件时，可以直接从 `SKILL.md` 的模板索引进入，不必完整走完本流程。

## 1. 定位任务

先写出一句话任务定义：产品类型、主要用户、核心动作、页面位置、成功标准。不要先写视觉方案。

示例：

> 做一个本地优先的 AI Agent 工具。用户需要同时跟踪多个任务，核心动作是创建任务、查看执行轨迹、恢复中断对话。成功标准是三列布局内不需要跳页完成主要工作。

如果用户只给出功能，没有参考产品，按“原创型工具”处理：由功能推导信息架构，再推荐风格。如果用户明确说“像 Codex / Notion / Magpie”，按“参考型项目”处理：学习其布局、信息层级和交互结构，不复制品牌视觉资产。

## 2. 信息架构

先列出页面区块和优先级，再决定组件：

1. 用户进入页面时最先要知道什么。
2. 最常见的一个操作是什么。
3. 哪些内容需要持续可见，哪些可以按需展开。
4. 哪些数据需要横向比较，哪些需要按时间理解，哪些属于对象详情。
5. 加载、空、无匹配、错误和恢复分别出现在哪里。

输出简版线框说明，例如：

```text
顶部：任务标题 + 运行状态 + 新任务
左侧：任务列表，按最近活动排序
中央：消息与执行轨迹，工具输出按需展开
右侧：仅在打开文件或详情时出现
底部：输入区、上下文附件、运行控制
```

## 3. 布局与组件选择

按 [layout-patterns.md](layout-patterns.md) 选择页面骨架，并说明弃用的方向。然后从五个模板中查找可用区块；只取需要的一块或几块，不复制整页外壳。

组件优先级：

1. 先用目标项目已有组件，并映射语义 token。
2. 缺口从 Universal UI 模板移植。
3. 仍没有时才新建，新建组件必须写明用途、尺寸、状态和键盘路径。

## 4. 风格选择

按 [style-selection.md](style-selection.md) 生成三个风格方向，由用户选择或混合。没有明确确认时，默认使用 Neutral Core；用户确认其他风格后，该风格成为本项目的锁定风格。

风格选择只决定表面、色彩、字体气质、密度、圆角、阴影和运动方式，不改变信息架构和数据口径。若某个风格会降低可读性或任务效率，在建议中明确指出。

## 5. 实现与边界

- 保留目标项目的路由、导航、数据接入和技术栈。
- 使用真实字段和真实操作路径；本地演示必须标注为演示。
- 状态、单位、时间范围、统计口径在图表、指标和表格之间保持一致。
- 不引入第二套基础组件库；能封装时先封装，不在业务层直接拼接底层控件。
- 不为了风格好看牺牲键盘、焦点、可读性和窄屏行为。

## 6. 交付与沉淀

交付前按 [visual-quality.md](visual-quality.md) 评分；低于 85 分先修再交付。用户要求沉淀本次选择时，交给 `$ui-preference-ledger`；Universal UI 只读取偏好，不写入偏好文件。
