# UI Preference Ledger

把一次 UI 选择沉淀为长期规则，避免把个人偏好和项目需求混在一起。个人偏好是全集，包含归纳规则和项目使用记录；项目偏好只写入当前项目，不能污染全局规则。

## 数据位置

- **全局个人 Profile**：`C:/Users/liuyd/.codex/design-profiles/universal-ui.md`；若当前系统用户不同，使用 `%USERPROFILE%/.codex/design-profiles/universal-ui.md`。
- **项目偏好**：优先写入当前项目 `DESIGN.md` 的 UI preference 小节；没有时再创建 `.agents/design-context.md`。
- **Skill 本体**：只保存记录和归纳流程，不写入任何用户项目信息。

调用本 Skill 并不自动授予写入权限。修改 Profile 或项目文件前，确认当前会话有明确用户授权；没有授权时只输出建议的记录内容。

## 工作模式

### record

用户说“记录 / 沉淀这次选择”时：

1. 提取本次会话中的产品类型、最终布局、最终风格、密度、明确偏好、被否决方向和理由。
2. 区分归属：
   - 用户明确说“以后”“我总是”“我讨厌” → 全局规则候选。
   - 由当前品牌、数据、技术栈或项目要求产生 → 项目偏好。
   - 只影响本次演示或一次性交付 → 不沉淀。
3. 归属清楚时直接写入对应文件；不清楚时先问用户选择全局、项目还是不沉淀。
4. 每次写入都要保留日期、场景、选择、理由和沉淀结果，不改写历史记录。

### summarize

用户说“归纳 / 总结我的偏好”时：

1. 读取全局 Profile 的使用记录。
2. 只把至少 2 次同方向出现、且没有后续反例的选择提升为规则。
3. 规则不超过 8 条，写成可直接执行的 UI 约束。
4. 保留原始使用记录；被后续选择推翻的规则标记为已废弃，不删除。

### review

用户说“查看我的 UI 偏好”时：

- 输出全局规则、项目偏好和最近使用记录。
- 指出全局与项目之间的冲突。
- 不主动修改文件。

## Profile 格式

`C:/Users/liuyd/.codex/design-profiles/universal-ui.md` 使用四段结构：

```markdown
# Universal UI Profile

## 全局规则

- Agent 工作台优先中央内容区，左栏保持窄，右侧详情按需打开。
- 数据页面使用中高密度，数字右对齐。
- 禁止卡片墙、嵌套卡片、装饰渐变和过度留白。

## 被否决方向

| 日期 | 方向 | 理由 |
| --- | --- | --- |

## 项目使用记录

| 日期 | 项目 / 场景 | 选择 | 理由 | 归属 |
| --- | --- | --- | --- | --- |

## 归纳说明

- 2026-11-18：初始版本来自 Universal UI 长期反馈基线。
```

## 项目偏好格式

`DESIGN.md` 的 UI preference 小节只写当前项目有效的内容：

```markdown
## UI preference

- 本项目锁定 Dark Command 风格。
- 左栏 240px，中央内容最大化，右侧详情按需打开。
- 本项目品牌色用于选中态，不做大面积背景。
```

项目品牌、真实字段、技术栈限制、导航结构、一次性演示要求都不写入全局规则。

## 冲突优先级

1. 用户本次明确要求。
2. 当前项目 `DESIGN.md`。
3. 全局个人 Profile。
4. Universal UI 默认规则。

个人偏好提供默认方向；项目约束覆盖个人偏好；本次明确指令覆盖项目约束。
